## 2. 后端审查（ZCode 主审）

### 2.1 新发现问题

**[P1] B-11 死文件簇：同名模块被包遮蔽，约 4000+ 行不可达代码仍在被维护**
- 实测方法：`django.setup()` 后逐一打印 `__file__`，`serializers/views/services/selectors` 全部解析到同名包的 `__init__.py`（Python 导入系统中包优先于同名模块）。
- 涉及文件（均被 git 跟踪）：`apps/assetmanagement/serializers.py`（1846 行）、`views.py`（1507 行）、`operation_log_service.py`（612 行，全仓零引用）、`services.py`、`selectors.py`。
- 维护误导证据：serializers.py 最后修改 2026-08-23（`32a6eb9` ruff 渐进修复），views.py / operation_log_service.py 最后修改 2026-08-24（`0aa99f9`/`1750bf7`）——**修复提交打在永不加载的文件上，等于白做**。
- 全部超 500 行且无 `TECHNICAL_DEBT` 标记（DR-5 风险面）。
- 修复方向：确认无 importlib 按路径加载后整体删除，1063 测试回归验证，预期零行为变更。

**[P3] BE-1 报废审批 reject/cancel 未对 Asset 加锁**
- `services/damaged_asset_service.py:209-211`（reject）与 `:271-273`（cancel）直接使用 `damaged_asset.asset_recordcode` 内存对象做 FSM 流转，未像 `create`（:46）与 `approve`（:142）那样 `select_for_update()` 重取，与 `state_machine/core.py:43-52` "调用方必须加锁"的契约不一致。
- 实际风险低（DamagedAsset 行已锁、damaged 态并发面窄），但模式不一致应统一。

**[P3] BE-2 规则文档缺口**
- `Rules_Fiels/backend-business-rules.md` §3 拒绝回退表缺 `damaged → repairing` 行；代码 `transitions.py:65` 有该路径且逻辑必需（repairing 可经 repair_failed 进入 damaged）。属文档漂移，补文档而非改代码。

**[P3] BE-3 strptime naive datetime 残留 4 处**
- `core/audit_log_views.py:171,177`、`apps/assetmanagement/operation_log_views.py:134,140`；本次 pytest 81 条 RuntimeWarning 的来源。USE_TZ 下按默认时区解释，跨时区部署时过滤边界偏移。建议统一 `make_aware`。
