 G-4：Nginx 启用 Gzip

 ### 方案

 conf.d 目录被 include 在 http 上下文，因此可在 default.conf.tpl 的 server 块之前添加：

 ```nginx
   # ===== Gzip 压缩(仅压缩文本类资源, 图片/字体已压缩不再处理) =====
   gzip on;
   gzip_vary on;
   gzip_min_length 1024;
   gzip_comp_level 5;
   gzip_types text/plain text/css application/javascript application/json
              image/svg+xml application/xml font/ttf font/woff font/woff2;

   server {
       ...原有内容不动...
   }
 ```

 防错要点：
 - 不压缩 image/*、video/*、已压缩格式（避免 CPU 浪费甚至体积膨胀）
 - gzip_vary on 确保 CDN/代理缓存正确区分压缩与否的变体
 - gzip_comp_level 5 而非 9：压缩率差异 <2% 但 CPU 成本翻倍
 - 验证：部署后 curl -sI -H "Accept-Encoding: gzip" https://域名/assets/js/xxx.js | grep -i content-encoding 应返回 gzip

 防错要点：
 - 新密码生成规则：≥20 字符混合集（可用 get_random_secret_key 思路）
 - postgres-exporter 的 DATA_SOURCE_NAME 引用同一 DB_PASSWORD 变量——随 env 自动更新，但需重启该容器
 - 禁止在提交信息、文档、对话中引用新密码明文
 - 监控栈若单独运行需同步其 env
