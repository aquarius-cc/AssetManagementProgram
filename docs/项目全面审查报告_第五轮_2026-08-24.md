## 二、P0 — 部署阻塞（容器无法启动）

### P0-1：`.dockerignore` 排除 `docker-entrypoint.sh`

- **文件**：`.dockerignore:92`
- **现象**：Dockerfile ENTRYPOINT 引用 `sh /app/docker-entrypoint.sh`，但该文件被 `.dockerignore` 排除，不会被复制到镜像中
- **后果**：容器启动后立即退出，报错 `entrypoint file not found`
- **修复**：从 `.dockerignore` 中移除 `docker-entrypoint.sh`

### P0-2：`gunicorn` 未在 requirements 中

- **文件**：`Dockerfile:51`、`requirements/base.txt`
- **现象**：Dockerfile CMD 调用 `gunicorn`，但 `requirements/base.txt` 中没有 `gunicorn`
- **后果**：容器启动后报错 `gunicorn: command not found`
- **修复**：在 `requirements/base.txt` 中添加 `gunicorn>=22.0.0`

### P0-3：WSGI/ASGI 协议不匹配

- **文件**：`Dockerfile:51`、`config/asgi.py`、`config/settings/base.py:349`
- **现象**：项目使用 Django Channels（ASGI），`ASGI_APPLICATION = "config.asgi.application"`，但 Dockerfile CMD 使用 gunicorn（WSGI 服务器）指向 `config.wsgi:application`
- **后果**：WebSocket 连接在生产环境不工作，ASGI 路由为死代码
- **修复**：将 CMD 改为 `daphne -b 0.0.0.0 -p 8000 config.asgi:application`

### P0-4：`daphne` 未在 requirements 中

- **文件**：`requirements/base.txt`、`config/settings/base.py:34`
- **现象**：`INSTALLED_APPS` 第一项是 `"daphne"`（注释："必须在最前面,启用 ASGI 模式支持 WebSocket"），但 `requirements/base.txt` 中没有 `daphne`
- **后果**：Django 启动时 `ModuleNotFoundError: No module named 'daphne'`
- **修复**：在 `requirements/base.txt` 中添加 `daphne>=4.1.0`

### P0-5：`channels_redis` 未在 requirements 中

- **文件**：`requirements/base.txt`、`config/settings/production.py:86-91`
- **现象**：`production.py` 配置 `CHANNEL_LAYERS` 使用 `channels_redis.core.RedisChannelLayer`，但 `requirements/base.txt` 中没有 `channels-redis`
- **后果**：生产环境启动时导入失败
- **修复**：在 `requirements/base.txt` 中添加 `channels-redis>=4.2.0`

### P0-6：`docker-compose.yml` 无 Redis 服务

- **文件**：`docker-compose.yml`
- **现象**：生产环境 `CHANNEL_LAYERS` 需要 Redis，但 `docker-compose.yml` 中没有 Redis 服务定义
- **后果**：Channel Layer 无法连接 Redis，WebSocket 功能不可用
- **修复**：在 `docker-compose.yml` 中添加 `redis:7` 服务
