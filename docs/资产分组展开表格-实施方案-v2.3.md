公开方法：`AssetGroupedSelector.list_group_summaries(*, user, filters, page, page_size) -> tuple[int, list[dict]]`，返回 `(分组总数, 当前页汇总行)`。

**偏离一：`_sort_group_rows` 取消，排序整体留在 SQL 侧**。原设计同时列了 Python 侧 `_sort_group_rows` 与 SQL 侧 `.annotate(_c_null).order_by(...)`，二者并存即两套排序实现（违反 DR-1）。取舍：排序与分页一并交由数据库 `ORDER BY` + `LIMIT/OFFSET`，Python 侧不二次排序。

**偏离二：nulls-last 改用 `F(path).asc(nulls_last=True)`（Django 4.1+），不用 `_c_null` 标记列**。实测原因：`F()` 表达式**不解析 lookup**，`F("...__contract_code__isnull")` 会被 Django 当作字段路径，去 `Contract` 上找名为 `isnull` 的字段并抛 `FieldError: Cannot resolve keyword 'isnull' into field`。`nulls_last=True` 由 Django 在 SQLite 上自行模拟，且**不在输出 dict 留下多余字段**（标记列方案会多一个 `_contract_is_null` 键污染序列化）。

**⚠️ 语义澄清（Q-3 / 用例 15 的前提）**：决策 13 中 `asset_count desc` 是**主排序键**，合同 nulls-last 是**次键**。故「哨兵组置末」**仅在 `asset_count` 相等时成立**——若哨兵组数量更高，它仍按主键排在前面。测试 `test_sentinel_group_first_when_count_higher` 专门锚定此行为，防止后来者硬编码「恒在末位」。

**null-safe 精确匹配**（组键元素 `k`、字段 `f`）：

```
k is None  →  Q(**{f + "__isnull": True})     # `=None` 在 SQL 中永不命中，会静默返回空集
otherwise  →  Q(**{f: k})
```

**三个设计决策**

1. **`get_group_key` 的顺序直接取 `GROUP_KEY_PATHS`，不写第二份字面量数组** —— 这兑现了 B4 docstring 里的承诺：编码侧（Serializer）与解码侧（Selector 的 `parse_group_key`）共用 B1 的唯一顺序声明。若两处各写一份数组，漂移会**静默**发生且形状校验仍通过（编码 `[A,B,C,D]` 解码成 `[A,C,B,D]` 长度不变）。
2. **`format_price` 提为模块级纯函数并独立测试** —— `price_display` 的格式化是业务规则（两位小数、`~` 分隔、升序），必须唯一实现；提为纯函数后可脱离 DB 参数化测 6 种输入（含 `Decimal("4500")` → `"4500.00"`、`0.5` → `"0.50"`）。
3. **两位小数用 `:.2f` 而非 `str(Decimal)`** —— `decimal_places=2` 只约束**存储**精度，聚合表达式（`Min`/`Max`）的返回精度取决于 DB；换库后若返回 `Decimal("4500")`，`str()` 会输出 `"4500"` 而契约要求 `"4500.00"`。

## §4 接口契约

信封以 `CustomPageNumberPagination.get_paginated_response`（`core/pagination.py:62-92`）实际输出为准：


⚠️ **`data.count` 是分页总记录数（分组总数），与 `data.results[i].asset_count`（组内资产条数）不是同一概念**，命名已刻意区分（D-3）。

### 3.12.7 sandbox 残留炸 lint 的完整收口（2026-10-05）

**故障现象**：`npm run test:mutate` 被 1 小时超时强杀后，`.stryker-tmp/sandbox-*` 残留；此后 `npx eslint .` 报 **1208 errors / exit 1**。删掉残留目录即恢复，故障与项目代码质量无关。

**真实机理**（逐环读源码核实，非推断）：

1. `tsconfig.app.json` 的 `include` 是 `["env.d.ts", "src/**/*", "src/**/*.vue"]`。sandbox 副本路径形如 `.stryker-tmp/sandbox-XXX/src/...`，**不落在任何 tsconfig 的 include 内**。
2. `@vue/eslint-config-typescript@14.7.0` 的 `dist/index.mjs:221,257` 为 `projectService: true`。
3. `typescript-eslint@8.59.2` 的 `useProgramFromProjectService.js:91` 抛出 `... was not found by the project service. Consider either including it in the tsconfig.json or including it in allowDefaultProject.`
4. 故每个被误 lint 的 sandbox 文件各失败一次，累计 1208 errors。

> ⚠️ **机理更正（早前表述有误，按 Fact-1 记录）**：本节早前写作「`tsconfigRootDir: __dirname` 解析**多候选**」，**错误**。`tsconfigRootDir` 是**单值**（指向项目根），不存在多候选解析行为。真实原因是上述 include 覆盖不到 sandbox 副本。结论不变（加 ignore 即清零），但机制描述以此处为准。

**为何不能依赖 stryker 自清**（`@stryker-mutator/core@10.0.0` 源码）：

| 退出方式 | `cleanTempDir: true`（原默认） | `cleanTempDir: "always"` |
|:---|:---|:---|
| 正常完成 | 清理 | 清理 |
| 进程内 JS 异常 | **不清理**（`stryker.js:56-65` catch 分支显式置 `removeDuringDisposal = false`） | 清理 |
| 被 SIGTERM/SIGINT 强杀 | 不清理 | **仍不清理** |
| CI `timeout-minutes` 触发 | 不清理 | **仍不清理** |

原因：`TemporaryDirectory.dispose()` 仅在 `stryker.js:32-33` 的 `finally { await rootInjector.dispose(); }` 中被调用；而信号路径由 `unexpected-exit-handler.js` 走 `process.exit(128+n)`，**Node 的 `process.exit()` 不执行 async `finally`**（进程立即退出，pending Promise 被丢弃）。该路径注册的两个 handler（`mutation-test-report-helper.js:40` 写增量报告、`sandbox.js:36` 还原原始文件）**均不删除临时目录**。故 schema 描述中「regardless of whether the run was successful」在实现上**不覆盖进程被杀**——本次事故正落在这一格。

**最终收口（2 处改动）**：

| # | 文件 | 改动 | 覆盖场景 |
|:---|:---|:---|:---|
| 1 | `stryker.config.json` | 顶层加 `"cleanTempDir": "always"` | 进程内 JS 异常路径 |
| 2 | `eslint.config.ts` | `'.stryker-tmp/**'` + 13 行机理注释 | **信号路径（主防线）** |

ignore 行是主防线的原因：它属 ESLint 侧配置，**不依赖 stryker 的任何行为**，无论进程怎么死都有效。`"always"` 则是 stryker 能自行处理的那部分。二者覆盖不同场景，非冗余。注释已写明「本条是主防线，不可删」，防止后人看到 `"always"` 后误删 ignore 行。

**已否决的备选方案（记录理由，避免重复讨论）**：

- **改 `tempDirName` 把 sandbox 挪出项目根**（已验证技术可行：`temporary-directory.js:16` 走 `path.resolve`、`child-process-proxy-worker.js:69-73` 按绝对路径 `process.chdir`，故不受位置影响），但收益不足且引入 3 项新风险：① `gitignore-writer.js` 读的是 `defaultOptions.tempDirName`（schema 默认值，非用户配置值），改配置后仍按 `.stryker-tmp` 追加忽略规则；② sandbox 落在父仓 `D:\CodeDemo\AssetManagementProgram\` 会进入父仓 ESLint/pytest/git 扫描范围（该处有 `.opencode/`、`scripts/` 等），等于把问题从子仓挪到父仓；③ `file-utils.js:85` 的 `path.basename(dir) === tempDirName` 按 basename 比对，带 `../` 的值永远匹配不上，会导致 `node_modules` 符号链接搜索把 sandbox 当普通目录遍历。

**证据边界（如实标注）**：
