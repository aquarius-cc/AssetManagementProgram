### 2.1 关键取舍说明

**为何 A4 不降级为 warning**：降级会让 `frontend/AGENTS.md §1.3` 的 `['error', 10]` 措辞与实现长期不一致，且需触发前端 §4.2 `[HALT]` 审批。step 级容错可同时满足「保持 error 语义」与「解除阻断」，且欠债在日志中完整可见。

**为何 step 级而非 job 级 `continue-on-error`**：官方文档仅说明 job 级「prevents a workflow run from failing」，**未说明 `needs` 交互与 UI 呈现**，第三方对此存在分歧（job 级下 job 仍显红叉、整体 workflow 是否报 failure 说法不一）。step 级语义明确、官方无争议、job 与 workflow 均转绿。代价是 52 条欠债在 UI 上退为警告，但日志完整。

**为何 mutmut 选 3.8.0 而非基线的 2.5.1**：3.x 换用 `mutants/` 目录架构（不再原地改写 + `.bak` 恢复），基线文档记录的最大坑自动消失；且默认开启依赖追踪（`track_dependencies=True`），增量重跑可大幅缩短耗时。代价是 65.63% 基线口径作废（见 §3.3）。
