### 2.2 发现的对齐问题

#### HIGH-1：维修状态映射键名不匹配

文件：`vue-assetmanagement/src/utils/statusMapping.ts:69`

前端当前（错误）：
```typescript
export const REPAIR_STATUS_MAP: Record<string, TagType> = {
  repairing: 'warning',    // <-- 键名错误
  completed: 'success',
  failed: 'danger',
}
```

后端实际枚举值：
```python
class RepairStatus(models.TextChoices):
    IN_PROGRESS = 'in_progress'  # <-- 正确值
    COMPLETED = 'completed'
    FAILED = 'failed'
```

影响：`repair_status === 'in_progress'` 的记录在前端无法匹配到标签样式，渲染为默认灰色。

修复：将 `repairing` 改为 `in_progress`。✅ 已修复（commit 90e2b6f）

#### LOW-1：分页响应类型不完整 ✅ 已修复

`AssetListResponse`、`OutAssetResponse` 等接口仅定义 `count/next/previous/results`，缺少后端实际返回的 `total_pages/page/page_size` 字段。TypeScript 结构化类型不影响运行时，但类型描述不完整。

修复：将 4 个独立接口替换为 `PaginatedResponse<T>` 类型别名（`asset.ts`、`outasset.ts`）。

#### LOW-2：Dashboard 死代码 ✅ 已修复

后端 `recent_asset_recordcodes` 端点（`dashboard_view.py:35-41`）与 `recent_out_assets` 功能重复，且无前端调用。

修复：删除 `recent_asset_recordcodes` 方法及对应测试类。

## 三、安全漏洞

### 3.1 CRITICAL（3 个）

#### C-1：start_django.py 内嵌多个严重漏洞 ✅ 已修复

文件：`vue-assetmanagement/start_django.py`（已删除，commit b942425）

| 行号 | 漏洞 | 描述 |
|:---|:---|:---|
| 67 | 硬编码 SECRET_KEY | `'django-insecure-test-key-for-development-only'` |
| 128 | CORS 全开 | `CORS_ALLOW_ALL_ORIGINS = True` |
| 149, 193 | CSRF 禁用 | `@csrf_exempt` 装饰器 |
| 159 | 硬编码凭证 | `username == 'admin' and password == '123456'` 绕过认证 |
| 161, 174 | 硬编码 JWT | 无需验证直接返回 token |
| 191 | 错误信息泄露 | `f"服务器内部错误: {str(e)}"` 暴露堆栈 |
| 262 | shell 注入风险 | `os.system("python manage.py runserver ...")` |

修复方式：删除整个脚本（死代码，与 `asset_management_backend/` 架构脱节，全仓无引用），并在 `.gitignore` 添加 `asset_backend/` 防护。

#### C-2：base.py SECRET_KEY 不安全默认值

文件：`asset_management_backend/config/settings/base.py:17`

```python
SECRET_KEY = config("SECRET_KEY", default="django-insecure-dev-only-key-change-in-production-1234567890")
```

若生产环境漏配 `SECRET_KEY` 环境变量，应用将以可预测密钥运行，JWT 可被伪造。`production.py` 已强制要求环境变量，但 `development.py` 未覆盖此默认值。

#### C-3：.env 含真实数据库密码

文件：`asset_management_backend/.env`

```
DB_PASSWORD=PostgresTerminal@8348*#*
```

虽然 `.dockerignore` 排除了 `.env`，但根 `.gitignore` 未列出 `.env` 文件。若后端目录重新初始化或 `.gitignore` 被编辑，密码将被提交。

### 3.2 HIGH（5 个）

#### H-1：WebSocket JWT 通过 URL 查询字符串传递

文件：`asset_management_backend/apps/notification/consumer.py:87-91`

连接 URL：`/ws/notifications/<jobcode>/?token=<access_token>`

JWT 会被 Web 服务器访问日志、浏览器历史、Referer 头记录。

#### H-2：前端 token "加密" 使用 XOR（非真正加密）

文件：`vue-assetmanagement/src/utils/tokenCrypto.ts:42-48`

XOR + 重复密钥可被任意逆向。加密密钥 `VITE_TOKEN_CRYPTO_KEY` 嵌入编译后的 JS 包中，任何人可通过 DevTools 提取并解密 localStorage 中的 token。

#### H-3：健康检查端点泄露数据库错误详情

文件：`asset_management_backend/config/urls.py:90`

```python
db_status = f"error: {e!s}"  # 暴露数据库连接串、主机名、版本
```

`/health/` 和 `/ready/` 端点无认证，异常时返回原始异常信息。

#### H-4：登录接口无账户级限流

文件：`asset_management_backend/apps/authusermanagement/views.py:221`

```python
throttle_classes = []  # 仅依赖全局 20/min 限制
```

攻击者可对单一账户每分钟尝试 20 次密码，分布式攻击则无限制。

#### H-5：.env.development 提交了 token 加密密钥

文件：`vue-assetmanagement/.env.development:17`

```
VITE_TOKEN_CRYPTO_KEY=dev_asset_mgmt_xk9f2m8q3j5n7p1r
```

结合 H-2（XOR 可逆），攻击者可解密所有 localStorage token。
