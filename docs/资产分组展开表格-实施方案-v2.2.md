## §3 实现拆分（修正后）

### 后端（assetmanagement，2 新增文件 / 端点 + 测试）

- **B1 — Selector** `AssetSelector.query_grouped_assets(user, filters)`：

- **B3 — 筛选透传**（修正 M-2）：在 grouped action 内组装既有筛选能力，**不改** list 端点 `filterset_fields`。
  - `asset_current_status` / `asset_type_recordcode` / `asset_storage_recordcode`（复用既有键）+ `contract_code`（精确）+ `no_contract`（`asset_contract_recordcode__isnull`）。
- **B4 — 明细端点**（修正 M-1）：新增 `AssetViewSet.@action(detail=False, url_path="group_children")`，契约见 §4.2。
  - 复用 `get_queryset_for_user` + 既有过滤映射，`AssetDetailSerializer`（含 `harddisk_sns`）分页返回。
- **B5 — 测试**：分组正确性 / 无合同归组 / 聚合值（count、单价区间）/ 行级 scope 隔离 / 筛选透传 / 汇总分页 count / group_children 与 grouped 同筛选下 count 一致 / RBAC 只读 / 响应信封格式（对齐 §4 信封）。

## §4 接口契约

> 统一响应根结构 `{code, message, data}`；分页信封以 `CustomPageNumberPagination.get_paginated_response` 实际输出为准（`core/pagination.py:82-92`）。
> 分页参数名 `page` / `page_size`（默认 20，上限 100 = `MAX_PAGE_SIZE`）。

### 4.1 汇总端点 `GET /assets/grouped/`

**Query 参数**

| 参数 | 类型 | 说明 |
|:--|:--|:--|
| `page` / `page_size` | int | 分页（默认 20 / 上限 100） |
| `asset_current_status` | str | 状态精确过滤（复用既有键） |
| `asset_type_recordcode` | str | 类型 recordcode 精确过滤（复用既有键） |
| `asset_storage_recordcode` | str | 仓库 recordcode 精确过滤（复用既有键） |
| `contract_code` | str | 合同编码精确过滤（新增） |
| `no_contract` | bool | `true` 时仅返回无合同哨兵组（新增） |

**响应（200）**

```json
{
  "code": 0,
  "message": "查询成功",
  "data": {
    "count": 120,
    "total_pages": 6,
    "page": 1,
    "page_size": 20,
    "next": null,
    "previous": null,
    "results": [
      {
        "group_key": "[\"HT00001\",\"笔记本电脑\",\"14寸/i5\",\"联想\"]",
        "contract_code": "HT00001",
        "contract_name": "采购合同-1",
        "asset_name": "笔记本电脑",
        "asset_specification": "14寸/i5",
        "asset_brand": "联想",
        "count": 3,
        "price_display": "4500.00",
        "asset_codes": ["ZC001", "ZC002", "ZC003"]
      }
    ]
  }
}
```

**字段说明**

- `group_key`：JSON 编码的四元组 `[contract_code|null, name, spec, brand]`，供前端缓存/展开标识（避免分隔符撞值）。无合同为 `[null, ...]`。
- `price_display`：`min==max` → `"4500.00"`；否则 → `"4500.00~5000.00"`（`~` 分隔，两位小数，升序）。
- `asset_codes`：该组全部资产编码（供级联全选，见 §2 决策 4；大组 payload 可接受，asset_code 短文本）。
- `count`：该组合计资产数。**口径见 [待确认] Q-2**。

### 4.2 明细端点 `GET /assets/group_children/`

**Query 参数**

| 参数 | 类型 | 说明 |
|:--|:--|:--|
| `contract_code` | str | 组键合同编码（精确） |
| `no_contract` | bool | `true` 时取无合同哨兵组（须与 grouped 汇总时一致，见不变量 I-1） |
| `asset_name` | str | 组键名称（精确） |
| `asset_specification` | str | 组键规格（精确） |
| `asset_brand` | str | 组键品牌（精确） |
| `asset_current_status` / `asset_type_recordcode` / `asset_storage_recordcode` | str | **必须透传与 grouped 相同的筛选**（见不变量） |
| `page` / `page_size` | int | 组内分页（默认 20 / 上限 100） |

**响应（200）**：`AssetDetailSerializer` 分页（含 `harddisk_sns`），信封同 §4.1。

**契约不变量（I-1）**：同一次筛选下，`group_children` 返回总数 == 对应组的 `grouped.count`。前端展开/组内翻页时**必须原样透传**当前 active 筛选参数，否则汇总数与明细数会漂移（这也是 B5 断言之一）。

## §5 字段映射确认清单（需业务逐项拍板）

| ID | 待确认项 | 现状 / 候选 | 影响面 |
|:--|:--|:--|:--|
| Q-1 | 「唯一标识码」列数据源 | 模型无对应单字段。候选 A：`harddisk_sns[].harddisk_sn_code`（一对多，需定多盘拼接策略，如 `ZC-HARD-001 / ZC-HARD-002`）；候选 B：新增 `asset_unique_code` 字段（§1.3 模型变更，触发 `[HALT]`） | 后端序列化 + 明细列 |

| Q-3 | 无合同哨兵组排序/标识 | 哨兵组 `group_key` 首元素为 `null`，排序置末（已定）；合同号列 "—" 由前端映射（`contract_code===null`） | B1 排序、前端渲染 |

| Q-5 | 明细列「资产分类/当前状态」显示值 | `AssetListSerializer` 已有 `asset_type_name`、`asset_current_status` 为 code；状态中文需前端 `StatusTag` 映射 | 前端列渲染 |
| Q-6 | 单价区间格式 | 本次定稿 `min~max`、两位小数、升序（见 §4.1） | B1 `price_display` |

## §6 门禁与登记

- 后端：全量 `pytest` + 覆盖率（Service 层 ≥90%）、`ruff check .`（含 C90）、`mypy . --strict`、`mutmut`。
- schema：重导出 `api-schema-baseline.json`（grouped / group_children 为纯新增端点，零契约破坏，oasdiff 由 CI 判定）。
- 前端：`type-check` / `lint` / `format:check` + `vitest --coverage --threshold 80`（Store 层 ≥90%）+ `test:mutate`。
- 登记：changelog + 审计票（必填项含 CT/DR/SC/跨端契约）。
- 边界留痕：明细与汇总瞬时竞态按实际条数回显不轮询；组内分页覆盖超长组无截断；单条组自动展开为纯前端展示层决策，后端无感知。

## §7 二期复用定性（修正表述）

组件 `GroupedAssetTable` + 聚合 helper 可复用；但**每页仍需**：① 分组键映射（各页字段名不同）② 分组口径业务确认（回收/损坏/报废页可能叠加审批状态）③ 遗失页需先核实/补合同字段。不建议表述为「零新代码」。聚合 helper（`query_grouped_*`）一期即参数化（分组键/聚合列/排序），二期只写映射，免二次重构。
