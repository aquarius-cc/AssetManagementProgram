## 1. 背景与目标

现有「资产分组」展开子区存在以下体验问题：

- 子区用「加载更多」方式：`loadMoreChildren` 以 `append=true` 追加下一页，导致 `childrenOf(groupKey)` 返回**已加载的全部页拼接**（如 20+20=40 条）一起渲染，给人“加载后的数据数量不对”的感受。
- 只能往前追加，**无法返回查看之前已加载的页**（回翻体验差）。
- **重大遗漏**：目标稿子行首列为 `[ ]` 勾选框。组级三态勾选（半选/全选/未选）依赖子行 `selection`，是 `GroupedAssetTable` 的核心特性（`GroupedAssetTable.spec.ts` 用例 1 完整覆盖该链路）。若不补充子区勾选列，会导致子区勾选消失、三态机制断链。
- 子表列偏冗余：目标视觉希望更聚焦「唯一标识码、资产编码、当前状态」三列。
- 展开子区与主表的 DOM/样式耦合风险（若强行嵌套 `<el-table>`）。

目标：

1. 将子区分页改为**真分页（可回翻）**：每页恰好展示 20 条当前页数据。
2. 子表结构：**首列勾选 + 序号 + 6 项透传字段 + 数量（恒为 1） + 操作**，共 10 列。
3. 抽出**独立可复用组件** `GroupedAssetChildTable.vue`，直接用于 `GroupedAssetTable.vue` 的 `#expand` 插槽，不动 `CommonList`。
4. 补全**子区受控勾选列**，完整接入既有组级三态勾选链路（零改动既有 selection 逻辑）。
5. 沿用现有服务端分页逻辑，仅补充**覆盖式跳页**入口 `goToChildPage`。
6. 列定义不新增第二定义源（DR-1），按白名单从 `AssetContentDetails` 明细列中过滤透传。

## 2. 核实的技术事实（关键）

### 2.1 useGroupChildrenCache.ts 实况

| 项 | 实况 | 结论 |
|---|---|---|
| **`childrenPage(groupKey)`** | 仅为**只读 getter**（返回已加载到的页码，未加载时按 `1` 处理），无 `setter`。 | 不能直接赋值实现“跳页”。 |
| **`loadMoreChildren(groupKey)`** | 固定调用 `fetchChildren(groupKey, page + 1, append = true)`，**纯追加**。 | 只能加载下一页，无法跳转到任意页、无法回翻。 |
| **`fetchChildren(groupKey, page, append)`** | 已实现：`append && previous ? [...previous, ...response.results] : response.results`。`append=false` 时**覆盖式写入**当前页 `results`。 | 请求层已支持覆盖式分页，只差一个对外入口。 |
| **`ensureChildren(groupKey, append=false)`** | 首次展开时用 `append=false` 拉取第 1 页。 | 覆盖式用法已有先例。 |
| **`childrenOf(groupKey)`** | 返回 `cache.items[groupKey] ?? []`。`append=true` 时会累积多页。 | 要实现“每页只渲染当前页”，必须用 `append=false` 覆盖写入。 |

结论：需新增 `goToChildPage(groupKey, page)`，内部调用 `fetchChildren(groupKey, page, false)`，复用现有 `loading` 防抖、错误处理逻辑。

### 2.2 重大遗漏：子区勾选列

`GroupedAssetTable.spec.ts` 用例 1（约 273-318）验证完整的组级三态链路：

> "组级勾选 > 明细行受控选中 > 取消 1 条 > selection-change > 组转半选"

该链路通过 `CommonList` 的 `$emit('selection-change')` 驱动。`GroupedAssetTable.vue` 内部已存在 `onChildSelectionChange`（约 223-228）与 `setGroupSelection` 逻辑。

因此 `GroupedAssetChildTable.vue` 必须：

- 首列增加 `type="selection"`（Element Plus 多选列）
- 使用**受控模式**：通过 `:selectedKeys: string[]` 控制选中项（键为 `asset_code`）
- `row-key` 固定为 `asset_code`，与现状 selection 键保持一致
- 暴露 `selection-change(rows: AssetDetail[])` emit，由父组件直接转发到既有 `onChildSelectionChange`

### 2.3 小修正要点

1. **白名单字段名（实况）**：`asset_specification`、`asset_brand`，而非 `specification`、`brand`（参 `AssetContentDetails.vue:195-197`）
2. **删除刷新路径**：`AssetContentDetails.vue:310-325` 的 `handleDelete` 成功回调需按 `enableGrouping` 分支刷新。分组页用 `groupedTableRef.value?.refresh()`，平铺页用 `smartListRef.value?.refresh()`（约 5 行改动，不新增 composable）
3. **total 取值**：直接用 `row.asset_count ?? 0`。`AssetGroupSummary` 无 `child_total` 字段，且 I-1 不变量 `asset_count ≡ asset_codes.length`

### 4.3 列结构与白名单

列结构：**首列 `type="selection"`（受控） + 序号（插槽） + 6 项透传字段 + 数量（固定 1，插槽） + 操作（插槽）**，共 10 列。

**白名单（6 列透传）：**

```text
recordcode
asset_code
asset_name
asset_specification
asset_brand
asset_current_status
```

过滤逻辑在 GroupedAssetTable.vue 内完成（见 6.2），组件仅渲染传入的 columns，不内建第二定义源（符合 DR-1）。
序号层级化：
${groupIndex}.${(currentPage - 1) * pageSize + page内序 + 1}
跨页连贯（如 1.20 → 翻页后首行 1.21）。
数量列：固定渲染 1，不取 row.quantity。
三列高亮： recordcode、asset_code、asset_current_status（通过 highlight-col 类名强化）。

## 5. composable 改动：useGroupChildrenCache.ts
### 5.1 新增方法
/**
 * 跳转到指定子明细页（覆盖式分页）
 * @description 使用 append=false 覆盖写入，确保每页仅渲染当前页数据（解决“加载更多”append 拼接导致的多页一起渲染问题）。
 * @note childrenPage 在覆盖式写入后表示「当前展示页（current display page）」，不再严格等同于「已加载最大页（max loaded page）」。
 *       该语义变更仅适用于分组子表真分页场景。
 */
async function goToChildPage(groupKey: string, page: number) {
    if (!groupKey) return
    await fetchChildren(groupKey, page, false)
}

### 6.2 子列定义（白名单过滤 + highlight）
const CHILD_WHITELIST_SET = new Set([
    'recordcode',
    'asset_code',
    'asset_name',
    'asset_specification',
    'asset_brand',
    'asset_current_status',
])

const childColumns = computed(() => {
  const src = assetDetailColumns.value ?? []
  return src
    .filter(col => {
      const p = (col as any).prop
      if (!p) return false
      return CHILD_WHITELIST_SET.has(p)
    })
    .map(col => ({
      ...col,
      className: ((col as any).className ? (col as any).className + ' ' : '') + 'highlight-col',
    }))
})
序号、数量、操作不在过滤列表内，由子组件插槽渲染。
### 6.3 展开插槽替换
