## 二、BLOCKING 问题（必须修复才能上线）

### B1 — 后端待迁移未执行

- **文件：** `apps/assetmanagement/migrations/`
- **现象：** `python manage.py makemigrations --dry-run` 生成 `0018_alter_outasset_outasset_type.py`
- **影响：** 运行时 OutAsset 查询报错，数据库 schema 与 ORM 不同步
- **修复：** 执行 `python manage.py migrate`

### B2 — 后端测试套件 ImportError

- **文件：** `apps/authusermanagement/tests/`
- **现象：** `python manage.py test --parallel` 崩溃，`ImportError: 'tests' module incorrectly imported`
- **影响：** 测试无法执行，CI 门禁完全失效
- **修复：** 检查 `authusermanagement/tests/__init__.py` 导入路径，修复模块发现机制

### B3 — 生产环境 API 地址硬编码 localhost

- **文件：** `vue-assetmanagement/.env.production:3`
- **现象：** `VITE_API_BASE_URL=http://127.0.0.1:8000/api/v1`
- **影响：** 任何非本地部署（Docker / 云服务器）都会 404
- **修复：** 改为相对路径 `/api/v1` 或通过 CI/CD 环境变量注入

### B4 — 无 CI/CD 工作流

- **文件：** `.github/workflows/`（空目录）
- **现象：** AGENTS.md 引用的 `duplicate-guard.yml`、`security-scan.yml` 均不存在
- **影响：** 所有 CT/SC/DR 红线不可自动执行，质量门禁形同虚设
- **修复：** 创建至少一个 CI workflow（test + lint + type-check）

### B5 — 前端 .env.* 文件提交到 git

- **文件：** `vue-assetmanagement/.env.production`、`.env.production.test`
- **现象：** 含 `VITE_TOKEN_CRYPTO_KEY` 密钥，已提交到版本库
- **影响：** 违反 SC-1 安全红线（禁止在代码仓库硬编码密钥）
- **修复：** `.gitignore` 覆盖 `.env.*`；考虑用 BFG 清理历史

### B6 — OutAssetType.REISSUE 前端缺失

- **后端：** `apps/assetmanagement/models/out_asset.py` — `OutassetType` 有 3 个值：`receive`、`borrow`、`reissue`
- **前端：** `src/types/outasset.ts:29-32` — `OutAssetType` 只有 2 个值：`receive`、`borrow`
- **前端映射：** `src/utils/Format.ts:361-364` — `outassetTypeMapping` 缺少 `reissue`
- **影响：** 后端返回 `reissue` 类型时，前端显示原始值 `"reissue"` 而非中文标签；无法创建 reissue 类型的出库记录
- **修复：** 在 `outasset.ts` 补充 `REISSUE = 'reissue'`，在 `Format.ts` 补充映射 `'reissue': '重新发放'`

## 三、WARNING 问题（应修复但不阻断运行）

### W1 — SECRET_KEY 不安全 fallback

- **文件：** `config/settings/base.py:17`
- **现象：** fallback 为 `django-insecure-dev-only-key-change-in-production-1234567890`
- **风险：** 开发环境可接受；若误用 `base.py` 配置部署到生产，密钥泄露
- **建议：** 生产配置已强制从环境变量读取，保持现状即可，但应在文档中明确标注

### W2 — ALLOWED_HOSTS=["*"] 仅限开发

- **文件：** `config/settings/development.py:30`
- **风险：** 误用 `DJANGO_SETTINGS_MODULE=config.settings.development` 到生产环境会暴露 Host header 攻击
- **建议：** 确保生产部署始终使用 `config.settings.production`

### W3 — URL 双重挂载

- **文件：** `config/urls.py:126-135`
- **现象：** 每个 API app 同时挂载到 `/api/v1/...` 和 `/api/...`（向后兼容）
- **风险：** drf-spectacular 产生 15+ 个 `W001` operationId 冲突
- **建议：** 下一版本移除 `/api/` 兼容前缀

### W4 — dev/test 依赖未 pin 版本

- **文件：** `requirements/dev.txt:31-34`、`requirements/test.txt:4-7`
- **现象：** `pytest`、`pytest-django`、`factory-boy`、`pytest-cov`、`coverage` 未锁定版本
- **风险：** 不同环境安装不同版本导致测试行为不一致
- **建议：** 补充 `==x.y.z` 版本锁定

### W5 — urllib3/chardet 版本不匹配

- **现象：** 运行时告警 `RequestsDependencyWarning: urllib3 (2.5.0) or chardet (6.0.0.post1) doesn't match a supported version`
- **风险：** `requests==2.32.5` 可能与系统级 `urllib3` 存在兼容性问题
- **建议：** 在 `requirements/base.txt` 中显式 pin `urllib3` 版本

### W6 — 无 404 catch-all 路由

- **文件：** `vue-assetmanagement/src/router/index.ts`
- **现象：** 未定义 `/:pathMatch(.*)*` 兜底路由
- **风险：** 用户访问不存在的路径时页面渲染空白，无友好提示
- **建议：** 添加 404 页面路由

### W7 — cssCodeSplit: false

- **文件：** `vue-assetmanagement/vite.config.ts:128`
- **现象：** 所有 CSS 打包为单文件
- **风险：** 首屏加载时传输未使用的样式，影响性能
- **建议：** 后续迭代中开启 CSS 代码分割

### W8 — 字段级验证错误 UX 降级

- **后端：** `core/exception_handler.py:56-60` — 字段错误放入 `data` 字段
- **前端：** `src/api/request.ts:182-186` — `pickErrorMessage` 只读 `detail/message/error`
- **现象：** 后端返回 `{ "asset_name": ["此字段不能为空"] }` 时，前端显示"参数验证失败"而非具体字段名
- **风险：** 用户体验降级，无法定位具体填写错误
- **建议：** 前端 `pickErrorMessage` 增加 `data` 字段解析逻辑

### W9 — INDEX.md 版本号漂移

- **文件：** `Project_Requirements/INDEX.md`
- **现象：**
  - 标注 AGENTS.md 版本 v3.4.1，实际 v3.5.0
  - 标注 backend-business-rules 版本 v1.3，实际 v1.8
- **风险：** 版本号不一致导致"单一索引源"失效
- **建议：** 同步更新 INDEX.md 中的版本号
