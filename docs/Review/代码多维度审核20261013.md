### 4.3 新发现：ci-cd.yml Dockerfile 路径疑点（R-02）【✅ 已修复 2026-10-13】

改动前 `ci-cd.yml` docker job 的 build 步骤（`file:` 行位于改动前 :110）：

```yaml
with:
  context: ./asset_management_backend
  file: Dockerfile
  push: true
```

`docker/build-push-action@v5` 的 `file` 输入语义：**原样透传给 buildx**——action 源码 `src/context.ts` 为 `args.push('--file', inputs.file)`，无任何相对 context 的重写逻辑；buildx 进程 CWD = `$GITHUB_WORKSPACE`（仓根），故 `--file Dockerfile` 相对仓根解析。仓根实测**无**该文件（`Test-Path Dockerfile` = False），真实文件在 `asset_management_backend/Dockerfile`。省略 `file` 时 action 不传 `--file`，buildx 回落默认 `{context}/Dockerfile` = `asset_management_backend/Dockerfile`（README inputs 表 `file` 默认值直证）。该步骤历史上从未真实执行到（Login 先失败于凭据，见 BF-067），路径缺陷一直被掩盖。

- **判定**：原静态推断为 `[推测]`（高置信）；2026-10-13 经 action 源码抓取直证后升级为**事实**并完成修复。
- **修复（方案①已执行）**：删除 `file:` 一行（自动取 `{context}/Dockerfile`），替换为 4 行防回归注释（含源码直证出处与修复日期）；少一处显式路径即少一处未来漂移点。
- **验证分层**：本地已验 YAML 语法解析通过 + `rg "file:"` 零实际输入命中（仅注释行含字样）；**真实生效验证留批次 1.4**（secrets 配好后 push 触发 CD，build 首次真实执行该路径）。回退预案：若 CI 仍报 Dockerfile not found，改方案② `file: ./asset_management_backend/Dockerfile` 再重跑。
