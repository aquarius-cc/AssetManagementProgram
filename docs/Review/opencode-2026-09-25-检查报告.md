## 3. 合规 / 达标结论（亮点）

- **状态机（CT-3 / BR 状态机）**：转换规则单一权威集中在 `state_machine/transitions.py:22-69`（VALID_TRANSITIONS），行为由 `state_machine/core.py` 与各 Mixin 实现；出库 / 回收 / 报废 / 报修 / 遗失找回等入口均 `@transaction.atomic` + 审计留痕 + 事务提交后通知。in_store 与 used-回归入池（repair_done / found_and_return 回到 recycled_pending）的语义在规则表注释中显式定义，scrapped 为终态。
- **权限与安全（SC-1~SC-8）**：RBAC 集中 `core/permissions.py`；行级隔离集中 `core/department_scope.py`；未发现密钥硬编码、SQL 拼接、未参数化查询；审计路由覆盖关键操作。
- **可观测性（OC）**：OC-1 trace_id 全链生成/透传/日志注入（`core/request_context.py:53-63`、`core/logging_filters.py:22-24`，前端 `src/api/request.ts:256-258` 回传 X-Request-ID）；OC-2 JSON 结构化日志（`core/json_formatter.py:20-42`）含 time/level/trace_id/message/module；OC-3 无敏感信息落盘；OC-4 Prometheus 指标已实现（QPS<10 按契约豁免 `[~]`）；OC-6 /health 与 /ready 带 DB+Redis 探测且有测试。
- **跨端契约（§3）**：响应包装 `utils/response_utils.py:23-53`（`code=0` 成功，错误 `code`=HTTP 状态）全业务视图一致，可执行视图中无裸 Response；资产状态 8/8 键完全对齐（后端 `asset.py:81-91` ↔ 前端 `statusMapping.ts:31-43`、`types/asset.ts:44-51`）；分页参数 page/page_size 一致（`pagination.py:34-36`）；时间输出 ISO8601+08:00（USE_TZ，无 DATETIME_FORMAT 覆盖）且前端 `Format.ts` 按本地时区解析；错误语义前后端分支逻辑自洽。
- **前端规范（F 系）**：F5（无硬编码品牌色/#fff/#000）、F10（全部 store 为 setup 语法）、F12（全组件 scoped）、FR-5（无 >500 行组件）、FR-6/FR-7/FR-8（composable/store 规模与嵌套合规）、store 不绕过 API 层。
- **AI 鲁棒性（AR-3/AR-4）**：真实出站调用均带超时与重试且配置驱动——飞书适配器 `docker/feishu-webhook/app.py:108-129`（urllib 超时 + 指数退避 + 环境变量注入）、`src/utils/tokenRefresh.ts:78-98,115-127`、axios `src/api/config.ts:13-20`。唯一异常为 dev-only 的 Q-07。
- **测试覆盖**：CT-1/CT-3 全路径用例存在且有状态机集成测试锚点；整体/核心覆盖率双达标（见 §1）；前端聚焦变异 90.83%。
