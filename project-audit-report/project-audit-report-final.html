2. CRITICAL — 运行时崩溃/数据错误（9 项）

CRIT-1 B 独有 待修复
asset_view.py 重复方法名 mark_broken 覆盖正确实现
文件定义了两个 mark_broken 方法（action）。第一个（~line 336）正确调用 AssetService.mark_asset_broken；第二个（~line 516）调用不存在的 mixin.mark_broken。Python 后定义覆盖前定义，正确实现成为死代码，运行时 AttributeError。
CRIT-2 B 独有 待修复
asset_view.py 重复方法名 mark_lost 覆盖正确实现
同 CRIT-1，mark_lost 也被第二个定义覆盖，调用不存在的 mixin.mark_lost。
CRIT-3 B 独有 待修复
asset_view.py mark_broken/mark_lost 参数名错误
重复定义传 description=，但 AssetLifecycleMixin.mark_asset_broken 需要 broken_reason=（必填），mark_asset_lost 需要 lost_reason=（必填）。TypeError。
CRIT-4 B 独有 待修复
out_asset_view.py 重复 get_queryset 导致 RBAC 行级隔离失效
第一个 get_queryset（~line 88）正确调用 OutAssetSelector.get_queryset_for_user() 做 RBAC 过滤。第二个定义（~line 110）覆盖了它且无 RBAC 过滤。所有出库查询绕过行级数据隔离，任何用户可看全部出库记录。
CRIT-5 B 独有 待修复
4 个 View 文件 ValidationError 未导入 → 运行时 NameError
asset_view.py:245,268、out_asset_view.py:203、recycle_asset_view.py:131、contract_view.py:79,171 的 catch 块使用 ValidationError，但文件仅导入了 AppValidationError。ValidationError 在这些模块中未定义，触发 except 时将抛出 NameError。
CRIT-6 A 独有 待修复
二维码展示与下载功能完全缺失
Asset 模型有 qr_code 字段（JSON 格式，unique 约束），但无自动生成逻辑。资产详情页无二维码区域，无下载/打印功能。需求规格中的核心交互缺失。
CRIT-7 A 独有 待修复
扫码页面未实现数据脱敏
ScanAssetView.vue 直接展示原始字段（价格、联系电话），设计文档要求价格显示 ****、电话脱敏（前3后4）。存在信息泄露风险。
CRIT-8 共同 待修复
测试覆盖率远低于 CT-2 门槛
后端 34 tests（+RBAC 59 tests），前端仅 4 个测试文件。CT-2 要求整体 ≥80%，核心模块 ≥90%。状态机全路径测试几乎空白，违反 CT-3。
CRIT-9 A 独有 待修复
8 个业务错误码未实现
规范定义的 2001(非法出库)/2002(资产已被领用)/2003(资产已登记)/3002(部门操作权限不足)/3003(超级管理员不可删除)/4002(部门下存在员工)/4003(部门下存在资产)/5001(数据库操作失败) 尚未定义。当前 BusinessCode 仅有 HTTP 状态码映射。

3. HIGH — RBAC 缺失/功能断裂（16 项）

HIGH-1 B 独有
recycle_asset_view.py get_queryset 未调用 RBAC 过滤
使用 RecycleAssetSelector.get_asset_recordcodes_for_list() 返回无过滤数据，所有用户可看全部回收记录。
HIGH-2 B 独有
damaged_asset_view.py 无 get_queryset 覆盖，无 RBAC 过滤
使用类级 queryset，所有用户可看全部待报废记录。
HIGH-3 B 独有
waste_asset_view.py get_queryset 未调用 RBAC 过滤
使用 WasteAsset.objects.for_list() 返回无过滤数据。
HIGH-4 B 独有
outasset_selector.py OutAssetSelector 方法返回 WasteAsset 查询集
get_asset_recordcodes_for_list() 和 get_asset_recordcodes_with_asset_details() 均返回 WasteAsset.objects.for_list()，明显是复制粘贴错误。
HIGH-5 B 独有
Selector get_by_asset_code 使用错误字段名
RecycleAssetSelector 和 DamagedAssetSelector 的 get_by_asset_code 方法用 asset_recordcode__recordcode 过滤，应为 asset_recordcode__asset_code。业务编码永远匹配不到。
HIGH-6 B 独有
useNotification.ts getJobcode() 永远返回 null
AuthInfo 存储对象仅有 auth_id/auth_username/isactive，无 employee_jobcode 字段。getJobcode() 查找该字段永远返回 undefined，WebSocket 永不连接，通知功能完全失效。
HIGH-7 B 独有
暗色模式 CSS 变量冲突（6 个变量值不一致）
dark.css 和 variables.css 均定义 html.dark 块，6 个 --el-* 变量值不同。dark.css 在后加载所以覆盖 variables.css 的值，导致自定义组件与 Element Plus 组件边框颜色不一致。
HIGH-8 A 独有
通讯录左树右联动布局完全缺失
设计文档要求 DepartmentTree + 部门信息区 + 人员区的完整交互，ContactsView.vue 仅为极简列表页（搜索框 + el-table + 分页）。
HIGH-9 A 独有
出库弹窗交互未实现
设计文档要求出库为弹窗（含借用类型、预计归还日期），当前为独立表单页 OutAssetForm.vue，无"借用"类型选择和"预计归还"字段。
HIGH-10 A 独有
公共组件 StatusTag/AssetSelect/EmployeeSelect 未封装
各页面重复内联 el-tag + 状态映射逻辑，违反 DR-2 组件原子化原则。资产选择器和员工选择器也未提取为公共组件。
HIGH-11 共同
报废审批工作流前后端断裂
后端 DamagedAssetViewSet 有 approve/reject action，但前端 damagedAsset.ts 无对应 API 方法。审批按钮无绑定 API，端到端工作流断裂。
HIGH-12 A 独有
数据导入导出仅部分实现
前端有 9 个 BatchImport 组件，后端有 batch_create 端点，但仅 Asset 模块配置了 ExportExcelMixin 导出列。其余模块无导出配置。
HIGH-13 A 独有
Service/Selector 层覆盖率约 65%
FoundAsset/RepairAsset/WasteAsset/AssetType/Storage/Contract 缺少独立 Service 层，OperationLog/RepairAsset/AuthUser 缺少独立 Selector 层。业务逻辑散落在 View 层。
HIGH-14 A 独有
找回后创建新资产 vs 恢复原资产
需求 AC-6 要求恢复原有资产状态为 in_store，当前实现创建新的 Asset 记录（或需确认 perform_create 具体逻辑）。
HIGH-15 A 独有
二维码无图片生成能力
Asset 模型有 qr_code JSON 字段但无自动生成二维码图片的逻辑，扫码接口返回 JSON 而非图片。
HIGH-16 A 独有
取消出库/取消回收 API 端点缺失
AssetFSM 定义了 cancel_outasset() 和 cancel_recycle()，但无 View action 暴露这些操作。用户无法撤回出库/回收操作。
