## 3. 安全要求

| 类别 | 要求 |
|------|------|
| 认证 | JWT认证，访问令牌2小时，刷新令牌7天 |
| 授权 | 基于RBAC模型，行级数据隔离 |
| 审计 | 所有状态变更记录日志，保留至少7年 |
| 脱敏 | 财务字段（购买价格）仅授权人员可见 |
| 限流 | 每分钟100次请求 |
| 二次确认 | 批量删除、状态变更等敏感操作 |

### 3.1 实现建议
- 使用DRF的权限类实现细粒度权限控制
- 敏感操作需要二次确认
- 所有API接口添加请求频率限制
- API接口使用HTTPS协议

### 3.2 审计日志
- 所有状态变更记录到AssetOperationLog（状态变更类 operation_type="state_change"，before/after_data 保存状态快照）
- 关键操作（删除、修改敏感字段）记录操作日志
- 日志保留至少7年（满足合规要求）

## 5. 可扩展性

1. **状态机扩展**：集中式设计，新增状态或转换只需修改`AssetFSM`
2. **业务记录扩展**：业务记录（OutAsset、RecycleAsset等）与资产主表解耦
3. **字段扩展**：支持通过配置实现自定义字段扩展（未来考虑）
4. **API版本管理**：使用 `/api/v1/` 前缀，后续版本升级通过版本号区分

## 6. 运维要求

### 6.1 监控指标
- API响应时间（P95、P99）
- 数据库连接池使用率
- 错误率统计
- 业务操作成功率

### 6.2 告警配置
- API响应时间超过3秒告警
- 错误率超过5%告警
- 数据库连接数超过80%告警
- 磁盘使用率超过80%告警

### 6.3 数据一致性检查
- 每日定时任务检查资产状态与业务记录一致性
- 发现不一致时生成告警日志并通知管理员
- 提供数据修复工具（需管理员权限）
