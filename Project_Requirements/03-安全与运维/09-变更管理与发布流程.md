# 变更管理与发布流程

**版本：V1.0**
**日期：2026-07-09**

---

## 1. 分支策略

```
main (生产)
  ├── develop (开发集成)
  │     ├── feature/T1-xxx (功能分支)
  │     ├── feature/T2-xxx
  │     └── bugfix/B3-xxx (修复分支)
  └── release/v1.0 (发布分支，可选)
```

| 分支 | 用途 | 合并方向 | 保护规则 |
|:---|:---|:---|:---|
| main | 生产代码 | - | 禁止直推，仅通过 PR 合并 |
| develop | 开发集成 | feature → develop | 禁止直推，需 1 人审批 |
| feature/* | 功能开发 | feature → develop | 自由分支 |
| bugfix/* | 缺陷修复 | bugfix → develop | 自由分支 |

## 2. PR 提交规范

### 2.1 PR 标题格式

```
[type](scope): summary

type: feat | fix | refactor | docs | test | chore
scope: backend | frontend | config | rules
summary: 简要描述（中文）
```

示例：
- `feat(backend): 新增资产出库接口`
- `fix(frontend): 修复资产列表分页参数传递错误`
- `docs(rules): 更新 backend-testing-rules T8 迁移验证`

### 2.2 PR 描述模板

```markdown
## 变更内容
- [ ] 新增/修改/删除了什么

## 关联任务
- 关联 T1 / T2

## 测试说明
- [ ] 已添加测试用例
- [ ] 所有测试通过
- [ ] 覆盖率检查通过

## 审计票
[粘贴审计票]

## 迁移说明（如有数据库迁移）
- [ ] 已执行 CT-6 三步验证
- [ ] 包含危险操作：是/否
```

### 2.3 Code Review 检查清单

审查者在 Review PR 时必须逐项核对：

| 检查项 | 依据 | 必须通过 |
|:---|:---|:---:|
| 审计票已填写且格式正确 | AGENTS §4 | 是 |
| 测试用例已添加且通过 | CT-1/CT-4 | 是 |
| 覆盖率达标（整体≥80%，核心≥90%） | CT-2 | 是 |
| 无硬编码密钥/密码 | SC-1 | 是 |
| 数据库查询使用参数化 | SC-3 | 是 |
| 文件上传有扩展名+大小校验 | SC-5/SC-6 | 是（如有上传） |
| 状态变更通过 FSM 方法 | B5/PRD-03 | 是（如有状态变更） |
| 函数行数≤50，文件行数≤500 | DR-5 | 是 |
| 圈复杂度≤10 | BR-5 | 是 |
| 跨端契约未破坏 | AGENTS §3 | 是 |
| 迁移文件已通过 CT-6 验证 | CT-6 | 是（如有迁移） |

## 3. 发布流程

### 3.1 日常发布（小变更）

```
feature 分支开发完成
  → 提交 PR（附审计票 + 测试结果）
  → Code Review（至少 1 人）
  → CI 全部通过
  → 合并到 develop
  → 自动部署到 test 环境
  → 验证通过
  → 合并到 main
  → 自动部署到 staging
  → 验证通过
  → 手动触发生产部署
```

### 3.2 正式发布（版本发布）

```
develop 功能冻结
  → 创建 release/vX.Y.Z 分支
  → 在 release 分支上修复 bug
  → 合并到 main + develop
  → 打 tag（vX.Y.Z）
  → 生产部署
  → 监控 30 分钟
  → 发布完成
```

## 4. 回滚方案

### 4.1 代码回滚

```bash
# 回滚到上一个版本
git revert HEAD
# 或回滚到指定 tag
git revert v1.0.0..v1.1.0
```

### 4.2 数据库回滚

> **重要**：仅允许回滚新增的迁移文件，禁止回滚已执行的数据迁移。

```bash
# 1. 检查最近的迁移文件
python manage.py showmigrations

# 2. 如果仅是新增表/字段，可安全回滚
python manage.py migrate <app> <上一个迁移文件名>
```

### 4.3 回滚决策

| 场景 | 回滚方式 | 责任人 |
|:---|:---|:---|
| 代码 Bug 导致功能异常 | git revert + 重新部署 | 开发负责人 |
| 数据库迁移导致问题 | 回滚迁移 + 代码回滚 | 后端开发 + DBA |
| 性能严重劣化 | 代码回滚 + 缓存清理 | 运维 |
