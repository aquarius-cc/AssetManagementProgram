# 数据备份与恢复方案

**版本：V1.0**
**日期：2026-07-09**

---

## 1. 备份策略

| 备份类型 | 频率 | 保留周期 | 存储位置 | 说明 |
|:---|:---|:---|:---|:---|
| 全量备份 | 每日凌晨 2:00 | 30 天 | 异地对象存储 | pg_dump 全库 |
| 增量备份 | 实时（WAL） | 7 天 | 本地 + 异地 | PostgreSQL WAL 归档（PITR） |
| Redis 快照 | 每小时 | 24 小时 | 本地 | RDB 文件 |

---

## 2. 备份执行脚本

```bash
#!/bin/bash
# backup.sh - 每日凌晨 cron 执行
BACKUP_DIR=/data/backups/postgres
DATE=$(date +%Y%m%d)
RETENTION_DAYS=30

# 全量备份
PGPASSWORD="$DB_PASSWORD" pg_dump -U backup_user \
  --format=custom \
  asset_management > "$BACKUP_DIR/full_$DATE.dump"

# 清理过期备份
find "$BACKUP_DIR" -name "full_*.dump" -mtime +$RETENTION_DAYS -delete

# 上传到异地存储
aws s3 cp "$BACKUP_DIR/full_$DATE.dump" s3://backup-bucket/postgres/ --storage-class STANDARD_IA
```

## 3. 恢复流程

### 3.1 全量恢复

```bash
# 1. 从备份文件恢复
pg_restore -U postgres -d asset_management --clean --if-exists full_20260709.dump

# 2. 应用增量 WAL（如需要）
# 恢复基础备份后，配置 restore_command 与 recovery_target_time，启动实例自动回放 WAL 实现 PITR，恢复到目标时间点

# 3. 验证数据完整性
python manage.py check --deploy
python manage.py migrate --check
```

### 3.2 单表恢复

```bash
# 仅恢复 assetstatelog 表
pg_restore -U postgres -d asset_management -t asset_management_assetstatelog full_20260709.dump
```
