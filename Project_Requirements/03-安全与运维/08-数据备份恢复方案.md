# 数据备份与恢复方案

**版本：V1.0**
**日期：2026-07-09**

---

## 1. 备份策略

| 备份类型 | 频率 | 保留周期 | 存储位置 | 说明 |
|:---|:---|:---|:---|:---|
| 全量备份 | 每日凌晨 2:00 | 30 天 | 异地对象存储 | mysqldump 全库 |
| 增量备份 | 实时（binlog） | 7 天 | 本地 + 异地 | MySQL binlog 同步 |
| Redis 快照 | 每小时 | 24 小时 | 本地 | RDB 文件 |

---

## 2. 备份执行脚本

```bash
#!/bin/bash
# backup.sh - 每日凌晨 cron 执行
BACKUP_DIR=/data/backups/mysql
DATE=$(date +%Y%m%d)
RETENTION_DAYS=30

# 全量备份
mysqldump -u backup_user -p"$DB_PASSWORD" \
  --single-transaction --routines --triggers \
  asset_management | gzip > "$BACKUP_DIR/full_$DATE.sql.gz"

# 清理过期备份
find "$BACKUP_DIR" -name "full_*.sql.gz" -mtime +$RETENTION_DAYS -delete

# 上传到异地存储
aws s3 cp "$BACKUP_DIR/full_$DATE.sql.gz" s3://backup-bucket/mysql/ --storage-class STANDARD_IA
```

## 3. 恢复流程

### 3.1 全量恢复

```bash
# 1. 从备份文件恢复
gunzip < full_20260709.sql.gz | mysql -u root -p asset_management

# 2. 应用增量 binlog（如需要）
mysqlbinlog --start-datetime="2026-07-09 02:00:00" binlog.000001 | mysql -u root -p asset_management

# 3. 验证数据完整性
python manage.py check --deploy
python manage.py migrate --check
```

### 3.2 单表恢复

```bash
# 仅恢复 assetstatelog 表
gunzip < full_20260709.sql.gz | mysql -u root -p asset_management asset_management_assetstatelog
```

## 4. 恢复演练

| 演练项目 | 频率 | 通过标准 |
|:---|:---|:---|
| 全量恢复 | 每季度 | RTO < 1小时，数据完整 |

## 5. RTO/RPO 验证

| 指标 | 目标 | 验证方法 |
|:---|:---|:---|
| RTO < 1小时 | 从备份恢复到服务可用 | 季度演练实测 |
| RPO < 15分钟 | 最多丢失 15 分钟数据 | binlog 延迟监控 |
