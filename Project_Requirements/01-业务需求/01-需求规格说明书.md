# 资产管理系统后端需求规格说明书

**版本：V2.6**
**日期：2026-07-09**
**状态：草案**

---

## 1. 引言

### 1.1 项目背景
随着企业资产规模扩大，传统的手工台账或简单电子表格已无法满足高效、准确、合规的管理需求。本系统旨在构建一套覆盖资产全生命周期的数字化管理平台，实现资产从入库、领用、使用、维修、报废到处置的全程可追溯、可审计、可管控。

### 1.2 目标
1. 建立统一的资产数据中心，实现"账实相符"。
2. 实现资产状态的实时监控与智能预警。
3. 规范资产流转流程，降低资产遗失、损坏风险。
4. 提供完整的审计留痕，满足内外部合规要求。
5. 支持未登记资产的发现与处理，弥补管理盲区。

### 1.3 适用范围
本系统适用于企业内所有固定资产、低值易耗品、IT设备、办公设备等的全生命周期管理，涵盖财务、行政、IT、生产等多个部门。

## 2. 总体说明

### 2.1 系统架构
系统采用前后端分离架构：
- **后端**：Django REST Framework + PostgreSQL，提供RESTful API。
- **前端**：Vue 3 + Element Plus，提供用户交互界面。
- **认证**：JWT（SimpleJWT）实现身份认证与授权。
- **权限**：基于RBAC模型，支持行级数据隔离。

**API版本管理**：所有接口统一使用 `/api/v1/` 前缀，后续版本升级通过版本号区分。

**分层架构**：View → Service → Selector → Serializer → Model（详见文档05-服务层设计）

### 2.2 RBAC权限矩阵

| 角色 | 资产出入库 | 报废审批 | 未登记资产处理 | 系统配置 | 审计日志查看 |
|------|-----------|---------|---------------|---------|-------------|
| 系统管理员 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 部门经理 | ✅（本部门） | ✅（本部门） | ✅（本部门） | ❌ | ❌ |
| 资产管理员 | ✅ | ❌ | ❌ | ❌ | ❌ |
| 普通用户 | 查看（本部门） | ❌ | ❌ | ❌ | ❌ |
| 审计员 | ❌ | ❌ | ❌ | ❌ | ✅ |

**角色详细说明**：
- **系统管理员**：拥有所有权限，包括系统配置、用户管理、部门管理等。
- **部门经理**：可管理本部门及下属部门的资产，拥有本部门的报废审批、未登记资产审批权限。
- **资产管理员**：负责日常资产出入库、损坏/遗失登记、维修等操作，但无审批权。
- **普通用户**：仅可查看本部门资产列表及详情，无法进行写操作。
- **审计员**：只读权限，可查看所有审计日志及资产历史，无业务操作权限。

**行级数据隔离规则**：
- 非管理员角色仅能查看本部门资产
- 通过DRF Permission + QuerySet Filter实现
- 部门层级关系由Department.parent_code字段维护

### 2.3 核心概念
- **资产（Asset）**：企业拥有的具有经济价值的实物或无形资产，每个资产拥有唯一的资产编码（asset_code）和系统内部编码（recordcode）。
- **资产类型（AssetType）**：资产的分类体系，如"笔记本电脑"、"服务器"、"办公桌椅"等。
- **仓库（Storage）**：物理存放资产的场所。
- **合同（Contract）**：采购合同信息，用于关联资产来源。
- **资产状态（Asset State）**：资产当前所处的生命周期阶段，是业务操作的核心依据。

## 3. 功能模块

| 模块名称 | 功能描述 |
|---------|----------|
| 资产管理 | 资产信息的增删改查、详情查看、盘点、状态变更查询、二维码生成与扫码查看 |
| 出库管理 | 资产领用/借用出库，记录使用人、保管人、使用地点、预计归还日期 |
| 回收管理 | 资产归还回库，支持正常回收、损坏回收、遗失回收，关联出库记录 |
| 损坏管理 | 标记资产损坏，记录损坏原因、描述，直接生效无需审批 |
| 遗失管理 | 标记资产遗失，记录遗失原因、最后位置，直接生效无需审批 |
| 找回管理 | 登记遗失资产的找回，恢复资产状态 |
| 维修管理 | 登记资产维修记录，跟踪维修过程，更新维修后物理成色 |
| 待报废管理 | 提交资产报废申请，进入审批流程（待审批→已批准/已拒绝） |
| 已报废管理 | 审批通过后正式报废，资产退出生命周期 |
| 未登记资产管理 | 处理实物有系统无、系统有无出库、状态异常三种场景 |
| 状态变更日志 | 记录资产每一次状态变更的详细历史，供审计追溯 |
| 资产类型管理 | 资产类型的增删改查，支持层级分类 |
| 仓库管理 | 仓库信息的增删改查（名称、位置、管理员、容量等） |
| 合同管理 | 采购合同的增删改查，关联资产来源 |
| 部门管理 | 部门树形结构的增删改查、层级管理（最大6层） |
| 员工管理 | 员工信息的增删改查、状态管理（在职/离职/退休） |
| 用户认证与授权 | 用户登录/登出、JWT令牌管理、密码重置、权限分配 |

## 4. 状态流转图
```markdown
                                    ┌──────────────────────────┐
                                    │         新增资产          │ (in_store)
                                    └──────────┬───────────────┘
                          ┌─────────────────────┼──────────────────┐
                          │ mark_broken         │ outasset         │ mark_lost
                          ▼                     ▼                  ▼
                   ┌────────────┐        ┌────────────┐     ┌────────────┐
                   │  已损坏     │        │  在用资产   │     │  已遗失     │
                   │ (broken)   │←───────│ (in_use)   │────▶│  (lost)    │
                   └──┬───┬────┘ mark_   └──┬──┬──┬───┘     └──┬───┬────┘
                      │   │    broken       │  │  │            │   │
      ┌───────────────┘   │                 │  │  │  damaged   │   │ 找回
      │ start_repair      │  recycle        │  │  └───────┐    │   │
      │                   │  (正常回收)     │  │          ▼    │   │
      ▼                   ▼                 │  │  ┌────────────┐   │   ┌──────────┐
┌────────────┐           │                 │  │  │  待报废     │   └──▶│ 找回记录 │
│  维修中     │           │                 │  │  │ (damaged)  │      │ (found)  │
│(repairing) │           │                 │  │  └──┬──────┬──┘      └──────────┘
└──┬──────┬──┘           │                 │  │     │      │
   │      │ repair_failed│                 │  │     │      │ reject
   │      └──────┐       │                 │  │     │      │ (按original_status)
   │             ▼       │                 │  │     │      ▼
   │  repair_done│       │                 │  │     │  ┌─────────┐
   │             ▼       ▼                 │  │     │  │broken/lost│
   │       ┌──────────────┐  recycle       │  │     │  │/recycled_ │
   │       │ 已回收待发放  │◀───────────────┘  │     │  │pending    │
   │       │(recycled_    │                   │     │  └─────────┘
   │       │  pending)    │──── 重新发放 ────▶│     │
   │       └──┬───────┬───┘                   │     │
   │   mark_  │        │  damaged             │     │
   │   broken │        └──────────────────────┘     │
   │   mark_  │                                     │
   │   lost   │  approve                            │
   │          ▼                                     │
   │    ┌────────────┐                              │
   │    │   已报废    │ [终态]                       │
   │    │ (scrapped) │◀─────────────────────────────┘
   │    └────────────┘         approve
   │
   └─── cancel_outasset ──▶ in_store / recycled_pending
```

**详细状态定义与转换规则**：参见文档03-业务规则与状态机

> **直转路径说明**：`in_use` 状态可直接通过以下操作转为其他状态（由 AssetFSM 校验合法性）：
> - `mark_broken` → `broken`（标记损坏）
> - `mark_lost` → `lost`（标记遗失）
> - `damaged()` → `damaged`（申请报废）
