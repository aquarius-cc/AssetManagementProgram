# 资产管理系统后端业务规则与状态机

**版本：V2.8**
**日期：2026-08-16**
**状态：草案**

---

## 1. 状态定义

| 状态代码 | 状态名称 | 说明 | 是否终态 |
|---------|---------|------|---------|
| in_store | 在库 | 资产在仓库中，未分配使用 | 否 |
| in_use | 在用 | 资产已被领用/借用，正在使用中 | 否 |
| recycled_pending | 已回收待发放 | 资产已回收，等待下次分配 | 否 |
| broken | 已损坏 | 资产存在但已损坏 | 否 |
| repairing | 维修中 | 资产正在维修（需创建维修记录） | 否 |
| lost | 已遗失 | 资产无法找到 | 否 |
| damaged | 待报废 | 资产损坏/遗失，等待报废审批 | 否 |
| scrapped | 已报废 | 审批通过，资产退出生命周期 | **是** |

---

## 2. 状态转换规则

| 当前状态 → 目标状态 | 转换方法 | 触发业务 |
|-------------------|---------|---------|
| in_store → in_use | outasset() | 出库 |
| in_store → broken | mark_broken() | 标记损坏 |
| in_store → lost | mark_lost() | 标记遗失 |
| in_use → recycled_pending | recycle() | 回收 |
| recycled_pending → in_use | outasset() | 再次出库 |
| recycled_pending → broken | mark_broken() | 标记损坏 |
| recycled_pending → lost | mark_lost() | 标记遗失 |
| recycled_pending → damaged | damaged() | 申请报废 |
| broken → repairing | repair() | 送修 |
| broken → damaged | damaged() | 申请报废 |
| repairing → recycled_pending | repair_done() | 维修完成 |
| repairing → damaged | repair_failed() | 维修失败 |
| lost → recycled_pending | found_and_return() | 找回 |
| lost → damaged | damaged() | 申请报废 |
| damaged → scrapped | approve() | 审批通过 |
| damaged → recycled_pending | reject() / cancel_damaged() | 审批拒绝/用户取消 |
| damaged → broken | reject_to_broken() | 审批拒绝（原状态为broken） |
| damaged → lost | reject_to_lost() | 审批拒绝（原状态为lost） |

**特殊回退操作**：

| 当前状态 → 目标状态 | 方法 | 说明 |
|-------------------|------|------|
| in_use → in_store/recycled_pending | cancel_outasset(previous_status) | 取消出库 |
| recycled_pending → in_use | cancel_recycle() | 取消回收 |
| 任意非终态 → recycled_pending | force_recycle_from_any() | 强制回收（管理员） |

## 3. 状态机代码实现

```python
class InvalidTransitionError(Exception):
    """非法状态转换异常"""
    pass


class AssetFSM:
    """资产状态机"""
    
    TRANSITIONS = {
        'in_store': {'to': ['in_use', 'broken', 'lost']},
        'in_use': {'to': ['recycled_pending', 'broken', 'lost']},
        'recycled_pending': {'to': ['in_use', 'broken', 'lost', 'damaged']},
        'broken': {'to': ['repairing', 'damaged']},
        'repairing': {'to': ['recycled_pending', 'damaged']},
        'lost': {'to': ['recycled_pending', 'damaged']},
        'damaged': {'to': ['scrapped', 'recycled_pending', 'broken', 'lost']},
        'scrapped': {'to': []}
    }
    
    def _validate_transition(self, asset, target_state: str) -> None:
        """校验状态转换是否合法"""
        current = asset.asset_current_status
        if current not in self.TRANSITIONS:
            raise InvalidTransitionError(f"未知状态: {current}")
        if target_state not in self.TRANSITIONS[current]['to']:
            raise InvalidTransitionError(
                f"不允许从 {current} 转换到 {target_state}"
            )
    
    def outasset(self, asset) -> None:
        """出库：in_store/recycled_pending → in_use"""
        self._validate_transition(asset, 'in_use')
        asset.asset_current_status = 'in_use'
    
    def recycle(self, asset) -> None:
        """回收：in_use → recycled_pending"""
        self._validate_transition(asset, 'recycled_pending')
        asset.asset_current_status = 'recycled_pending'
    
    def mark_broken(self, asset) -> None:
        """标记损坏：in_store/in_use/recycled_pending → broken"""
        self._validate_transition(asset, 'broken')
        asset.asset_current_status = 'broken'
    
    def mark_lost(self, asset) -> None:
        """标记遗失：in_store/in_use/recycled_pending → lost"""
        self._validate_transition(asset, 'lost')
        asset.asset_current_status = 'lost'
    
    def repair(self, asset) -> None:
        """送修：broken → repairing"""
        self._validate_transition(asset, 'repairing')
        asset.asset_current_status = 'repairing'
    
    def repair_done(self, asset) -> None:
        """维修完成：repairing → recycled_pending"""
        self._validate_transition(asset, 'recycled_pending')
        asset.asset_current_status = 'recycled_pending'
    
    def repair_failed(self, asset) -> None:
        """维修失败：repairing → damaged"""
        self._validate_transition(asset, 'damaged')
        asset.asset_current_status = 'damaged'
    
    def found_and_return(self, asset) -> None:
        """找回：lost → recycled_pending"""
        self._validate_transition(asset, 'recycled_pending')
        asset.asset_current_status = 'recycled_pending'
    
    def damaged(self, asset) -> None:
        """申请报废：recycled_pending/broken/repairing/lost → damaged"""
        self._validate_transition(asset, 'damaged')
        asset.asset_current_status = 'damaged'
    
    def approve(self, asset) -> None:
        """审批通过：damaged → scrapped"""
        self._validate_transition(asset, 'scrapped')
        asset.asset_current_status = 'scrapped'
    
    def reject(self, asset) -> None:
        """审批拒绝（通用）：damaged → recycled_pending"""
        self._validate_transition(asset, 'recycled_pending')
        asset.asset_current_status = 'recycled_pending'
    
    def reject_to_broken(self, asset) -> None:
        """审批拒绝（原状态为broken）：damaged → broken"""
        self._validate_transition(asset, 'broken')
        asset.asset_current_status = 'broken'
    
    def reject_to_lost(self, asset) -> None:
        """审批拒绝（原状态为lost）：damaged → lost"""
        self._validate_transition(asset, 'lost')
        asset.asset_current_status = 'lost'
    
    def cancel_damaged(self, asset) -> None:
        """用户取消报废申请：damaged → recycled_pending"""
        self._validate_transition(asset, 'recycled_pending')
        asset.asset_current_status = 'recycled_pending'
```
## 4. 业务规则与约束
### 4.1 状态流转合法性
1.任何状态变更必须通过 `AssetFSM` 提供的转换方法，不可直接修改 `asset_current_status`。

2.所有转换方法会校验当前状态是否允许转换到目标状态。

3.`scrapped` 为终态，不允许任何转出。

### 4.2 并发控制
1.使用乐观锁（`version` 字段）防止并发更新冲突。

2.涉及状态变更的关键事务使用 `select_for_update()` 行级锁。

3.并发冲突时返回明确错误信息（"资产已被其他用户操作，请刷新后重试"）。

### 4.3 事务要求
1.涉及状态变更的业务操作必须在同一个数据库事务中完成。

2.使用 `@transaction.atomic` 装饰器包裹核心业务方法。

3.事务中任意步骤失败，所有变更回滚。

### 4.4 数据一致性
1.资产主表中的 `asset_current_status` 必须与最新的业务记录保持一致。

2.例如，存在未回收的出库记录时，资产状态应为 `in_use`。

3.系统应提供定期一致性检查任务，发现异常自动告警。

### 4.5 软删除策略
1.所有核心模型支持软删除（`is_deleted` 标记）。

2.删除操作仅标记 `is_deleted=True`，数据保留用于审计。

3.唯一约束需配合 `condition=models.Q(is_deleted=False)` 实现。

### 4.6 状态变更日志
1.每次状态变更必须留痕,当前实现由 `AssetOperationLog`(`OperationLogService`/`AuditLogger`)履行——按操作类型记录 before/after_data,覆盖全部 16 种操作,满足审计查询。

2.`AssetStateLog` 表(需求 §15)已建但**未启用**。产品决策已定：状态变更审计统一由 `AssetOperationLog` 履行，`AssetStateLog` 不启用写入；后续若有独立状态轨迹需求（如轨迹回放、差异化查询），可基于 `AssetOperationLog.before_data/after_data` 演进或另行评审启用该表，决策前禁止新增对该表的依赖。

3.日志包含操作人、关联单据号、变更原因（可选）。

4.日志不可修改或删除，仅提供查询接口。

### 4.7 组织与用户管理规则
1.**部门层级**：最多6层（level 0~5），根部门level=0。

2.**部门删除**：若部门存在未删除的子部门或关联员工，禁止删除。

3.**员工状态**：仅`active`状态的员工可被选为资产保管人、申请人。

4.**用户激活**：`auth_is_active=False`的用户无法登录。

5.**密码策略**：密码长度至少8位，包含字母和数字。

6.**登录安全**：连续登录失败 5 次后，账户锁定 15 分钟。

7.**令牌管理**：Access Token有效期2小时，Refresh Token有效期7天。

## 5. 异常处理机制
### 5.1 异常类型与错误码
| 异常类型	| 错误码	| HTTP状态码	| 说明 |
| :--- | :--- | :--- | :--- |
| `InvalidTransitionError`	| 1001|400|非法状态转换|
|` ConcurrentUpdateError`	|1002|409|并发更新冲突|
| `AssetNotFoundError`	|1003|404|资产不存在|
|`ValidationError`	|2001|400|数据校验失败|
| `FieldRequiredError`	|2002|400|必填字段缺失|
| `PermissionDeniedError`	|3001|403|无操作权限|
| `BusinessRuleError`	|4001|400|业务规则违反|
| `DatabaseError`	|5001|500|数据库错误|
### 5.2 响应格式规范
**成功响应**：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```
**错误响应**：

```json
{
  "code": 1001,
  "message": "操作失败",
  "data": {
    "error_type": "InvalidTransitionError",
    "detail": "当前状态(in_use)不允许标记损坏",
    "suggestion": "请先回收资产后再标记损坏"
  }
}
```
### 5.3 业务流程异常
|异常场景	|处理方式|
| :--- | :--- |
|维修过程中资产再次损坏	|允许创建新的损坏记录，但资产状态保持 `repairing`|
|找回的资产与原遗失资产不匹配	|提示"找回资产编码与原遗失资产不匹配"|
|审批人与申请人为同一人	|提示"审批人不能与申请人为同一人"|
|批量操作部分失败	|逐条执行，成功记录继续处理，失败记录返回错误|
