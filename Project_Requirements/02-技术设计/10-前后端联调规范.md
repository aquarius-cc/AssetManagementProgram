# 前后端联调规范

**版本：V1.0**
**日期：2026-07-09**

---

## 1. 接口文档消费方式

### 1.1 OpenAPI 在线文档
- 后端启动后访问 `http://localhost:8000/api/docs/` 查看 Swagger UI
- 环境变量 `SPECTACULAR_VISIBLE_URL` 控制对外暴露地址

### 1.2 前端 Mock 方案

**开发阶段**：使用 MSW (Mock Service Worker) 拦截请求

```typescript
// src/mocks/handlers/asset.ts
import { http, HttpResponse } from 'msw'

export const assetHandlers = [
  http.get('/api/v1/assets/', () => {
    return HttpResponse.json({
      code: 0,
      message: 'success',
      data: {
        results: [...],
        count: 150,
      }
    })
  }),
]
```

**Mock 数据生成**：使用 faker.js 生成符合字段校验规则的测试数据。

### 1.3 接口变更通知
- 后端修改 API 后须更新 OpenAPI schema
- 前端通过 `openapi-typescript` 自动生成 TypeScript 类型
- 破坏性变更须在 PR 描述中标注 `[BREAKING]`

## 2. 联调环境配置

| 配置项 | 开发环境 | 联调环境 |
|:---|:---|:---|
| API 地址 | VITE_API_BASE_URL=http://localhost:8000/api/v1 | VITE_API_BASE_URL=http://test-api.internal/api/v1 |
| Mock 模式 | 开启 | 关闭 |
| 代理 | Vite dev server proxy | Nginx 反向代理 |

### 2.1 Vite 代理配置（开发）

```typescript
// vite.config.ts
export default defineConfig({
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:8000',
        changeOrigin: true,
      }
    }
  }
})
```

---

## 3. 联调流程

```
后端开发完成接口 → 提交 PR + 更新 OpenAPI
       ↓
前端拉取最新 API 类型 → 使用 MSW Mock 开发
       ↓
后端部署到 test 环境 → 前端切换到 test API
       ↓
联调验证 → 发现问题 → 各自修复
       ↓
联调通过 → 各自补充测试 → 合并
```
